# Acessibilidade (WCAG 2.2 AA aplicado)

AA é o mínimo contratual de todo projeto WebCode. Acessível também é mais rápido para todo mundo: teclado, contraste e alvos grandes ajudam o usuário apressado tanto quanto o usuário com deficiência.

## Percepção
- [ ] Contraste: texto 4.5:1, texto grande (≥ 24px ou ≥ 18,66px bold) 3:1, bordas de controles, ícones e foco 3:1. Os tokens já garantem; você garante ao combinar (texto sobre imagem, gradiente, vidro). WCAG 2.2 é o contrato; APCA (proposta do WCAG 3) só como segunda opinião em texto fino ou claro sobre escuro, onde a razão 2.x engana. Nunca troque um pelo outro para "passar".
- [ ] Informação nunca só por cor (status, erro, link dentro de texto tem sublinhado).
- [ ] Imagem informativa tem `alt` que diz o que ela comunica; decorativa tem `alt=""`. Ícone decorativo `aria-hidden="true"`.
- [ ] Texto redimensionável até 200% e reflow em 320px de largura sem scroll horizontal (exceto tabelas e mapas).
- [ ] Vídeo com legenda; áudio com transcrição; nada pisca mais de 3 vezes por segundo.
- [ ] `lang="pt-BR"` no `<html>`; trechos em outra língua com `lang`.

## Teclado e foco
- [ ] Tudo que funciona com mouse funciona com teclado, em ordem que segue a leitura. Nada de `tabindex` positivo.
- [ ] Foco sempre visível com `--wc-focus` (anel de 2px com 3:1 contra o fundo). `:focus-visible`, nunca `outline: none` sem substituto.
- [ ] **2.4.11 Foco não encoberto:** header sticky, cookie banner ou toast não escondem o elemento focado. Use `scroll-padding-top` igual à altura do header.
- [ ] **2.4.13 Aparência do foco (AAA, meta WebCode):** área do anel ≥ perímetro de 2px do componente e contraste 3:1 entre focado e não focado.
- [ ] Link "Pular para o conteúdo" como primeiro foco em sites e apps com navegação longa.
- [ ] Overlays: foco entra no primeiro elemento útil, fica preso enquanto modal, Esc fecha, foco volta ao gatilho.
- [ ] Atalhos de tecla única (sem modificador) podem ser desligados ou só valem com o foco no componente (2.1.4).

## Ponteiro e toque
- [ ] **2.5.8 Tamanho do alvo:** mínimo 24×24 CSS px (AA). Meta WebCode: 44×44 no toque (`--wc-size-touch-min`), com hit area invisível quando o desenho é menor.
- [ ] **2.5.7 Movimentos de arrastar:** tudo que se faz arrastando tem alternativa por clique (reordenar com botões ↑↓ ou menu "Mover para", sheet fecha com botão/Esc, slider aceita clique na trilha e setas).
- [ ] Ação dispara no `up`, não no `down`, para o usuário poder desistir arrastando para fora (2.5.2).
- [ ] Gestos complexos (pinça, dois dedos) têm alternativa com um toque.

## Formulários
- [ ] Todo campo tem `<label>` visível e associado. Placeholder não é rótulo.
- [ ] Erro identificado em texto, ligado ao campo por `aria-describedby` e `aria-invalid="true"`; resumo de erros no topo em formulários longos, com links para cada campo.
- [ ] `autocomplete` correto (`name`, `email`, `tel`, `postal-code`, `cc-number`, `one-time-code`…) para preenchimento automático (1.3.5).
- [ ] **3.3.7 Entrada redundante:** dado já informado no fluxo vem preenchido ou selecionável ("Mesmo endereço de entrega").
- [ ] **3.3.8 Autenticação acessível:** login não exige memorizar, transcrever ou resolver quebra-cabeça. Permita colar senha, gerenciador de senha, passkey, link mágico; CAPTCHA só com alternativa.
- [ ] Tempo limite avisado com opção de estender (2.2.1).

## Leitores de tela e semântica
- [ ] HTML semântico primeiro: `button` para ações, `a` para navegação, `nav`, `main`, `header`, `footer`, títulos `h1–h6` em ordem sem pular nível.
- [ ] Um `h1` por página. Landmarks com rótulo quando houver mais de um do mesmo tipo (`nav aria-label="Principal"`).
- [ ] ARIA só quando o HTML não resolve, e seguindo o padrão do WAI-ARIA APG (dialog, tabs, combobox, menu, grid). ARIA errado é pior que nenhum.
- [ ] Mudanças dinâmicas anunciadas: toast e status em `role="status"` (polido), erro crítico em `role="alert"`. Não anuncie tudo.
- [ ] Nome acessível igual (ou começando igual) ao texto visível (2.5.3), para comando por voz funcionar.
- [ ] Tabelas de dados com `<th scope>` e `<caption>`; não use tabela para layout.

## Movimento e preferências
- [ ] `prefers-reduced-motion`: deslocamento, parallax e zoom viram fade curto ou nada (`--wc-motion-distance: 0`).
- [ ] Nada se move sozinho por mais de 5s sem pausa (carrossel, ticker, vídeo de fundo) (2.2.2).
- [ ] `prefers-reduced-transparency` e `prefers-contrast: more` respeitados (vidro vira sólido, bordas ficam mais fortes).
- [ ] Modo escuro conferido com o mesmo rigor do claro.

## Como testar (10 minutos por tela)
1. Só teclado: Tab, Shift+Tab, Enter, Espaço, Esc, setas. Chegou em tudo? Viu o foco o tempo todo?
2. Zoom 200% e largura 320px.
3. axe DevTools ou `npm run verify` do site (axe + foco por Tab).
4. Leitor de tela no fluxo principal: VoiceOver (macOS/iOS) ou NVDA (Windows).
5. Reduced motion e alto contraste ligados no sistema.
